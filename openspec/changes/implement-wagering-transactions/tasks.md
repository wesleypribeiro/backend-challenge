## 5. Independent Review Fixes

- [x] 5.1 WIN with an explicitly informed optional reference whose target is missing (or not yet `PROCESSED`) transitions to `PENDING_REFERENCE` (domain `waitsForReference()`); a WIN without a reference still processes normally. Integration tests on real PostgreSQL: WIN without reference → processed; WIN with existing valid BET → processed; WIN with missing reference → `PENDING_REFERENCE` persisted with no credit and no ledger entry; idempotent resubmission replays the pending outcome with no new events.
- [x] 5.2 Pending-reference semantics corrected: the early `PENDING_REFERENCE` REFUND is never declared resolved by a later BET arrival or by a new submission. Idempotent resubmission replays the pending result; a fresh-key REFUND applying after the BET is documented as a distinct transaction. The F5 reprocessing contract (reprocess the same row, preserve its transactionId, re-check `DUPLICATE_REVERSAL` to avoid double credit) is recorded in `design.md` D14 and the specs.
- [x] 5.3 Structural validation of business identifiers (`providerId`, `externalTransactionId`, `idempotencyKey`, `roundId`, `gameId`, `playerId`, `walletId`, optional `referenceExternalTransactionId`): string type, non-empty, per-field size limits, UUID form for player/wallet. Violations raise `InvalidBusinessIdentifierError` (field-named) before any SQL transaction — never a persisted rejection or partial write. Unit tests plus PostgreSQL integration tests asserting zero writes.
- [x] 5.4 OPENING integration events per README §11: the internal `OPENING` transaction commits `WagerTransactionProcessed` + `WalletBalanceChanged` in the same flush as wallet, transaction and ledger (no publication — F4); zero-balance opening emits nothing.
